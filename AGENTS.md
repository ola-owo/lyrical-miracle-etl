# Overview

This is an ETL pipeline that retrieves a user's music listening activity
and processes it for downstream analyses.

# Tech stack

- airflow: pipeline orchestration
- [dlt](https://dlthub.com/docs/llms.txt): data extraction, transformation, and loading
- [neon](https://neon.com/docs/llms.txt): postgresql database for storing pipeline data
- polars and pyarrow: dataframe manipulation
- sqlalchemy and psycopg2: storing/loading pipeline data from postgres
- duckdb: storing/loading data locally when testing

# Project layout

This is a `uv` Python project with `pyproject.toml` serving as the project manifest.
The actual python scripts are in `data_loader/`.

`Dockerfile` and `docker/` contain scripts necessary for builiding and running the Docker container.

`schemas/` contains data schemas generated by dlt ([as seen here](https://dlthub.com/docs/walkthroughs/adjust-a-schema)).

# Guidelines

- Provide type hints and doc strings for all non-trivial python functions
- Run Python scripts through `uv` when possible
- Run external python tools through `uvx` when possible
- Prefer `Pathlib` over `os.path`

# Sandbox mode

For security reasons, you may be in a sandbox with restricted access to the internet or files outside the sandbox.
Some tips to mitigate this are:

- use normal sandboxed commands for local file work
- set `UV_CACHE_DIR=/tmp/uv-cache` when running any `uv` commands inside this sandbox
- request approval before running commands that access information outside the sandbox
- if a command fails due to sandbox restrictions,
  request approval from the user to run it again with escalated privileges.
